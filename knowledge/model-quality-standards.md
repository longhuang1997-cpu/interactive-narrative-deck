# 专业商业模型质量标准

> **核心原则**：不做假专家，只在真正理解方法论的前提下生成可视化。

---

## 🎯 四大质量标准

### 1. 视觉精美度（Professional Visual Quality）

**问题**：现在的实现像是"PPT形状堆砌"，缺乏专业商业分析工具的质感。

**标准**：
- ✅ 精细的图形绘制（SVG路径，不是简单的div+border）
- ✅ 克制的配色（参考Tableau/Power BI配色规范）
- ✅ 专业的排版（网格对齐、黄金比例、视觉层次）
- ✅ 微交互反馈（hover显示详情、点击展开、动画缓动函数）
- ✅ 数据密度合理（信息/像素比例符合Tufte原则）

**参考基准**：
- McKinsey报告的图表质量
- Tableau Dashboard的交互体验
- FigJam/Miro的协作看板
- D3.js Gallery的可视化案例

---

### 2. 思维密度（Analytical Depth）

**问题**：只展示了数据容器，没有体现分析方法论的深度。

**标准**：
- ✅ 嵌入分析逻辑（不只是展示，要引导思考）
- ✅ 关键洞察提示（高亮异常值、标注趋势、显示相关性）
- ✅ 决策支持信息（基于模型给出建议，不是纯展示）
- ✅ 分析过程可追溯（显示计算逻辑、数据来源）

**案例对比**：

❌ **低密度（当前实现）**：
```
BCG矩阵：4个气泡散点，仅显示位置
```

✅ **高密度（目标实现）**：
```
BCG矩阵：
- 气泡散点 + 象限名称 + 战略建议
- 10%分界线（虚线标注）
- 气泡大小映射营收规模（带数值标签）
- hover显示：市场份额%、增长率%、营收、战略建议
- 异常检测：标红市场份额<10%的"瘦狗"业务
```

---

### 3. 数据前置条件（Data Validation）

**问题**：没有数据验证规则，随意输入就能生成。

**标准**：每个模型必须定义：
- ✅ 必填字段 vs 可选字段
- ✅ 数据类型约束（数值范围、文本长度、枚举值）
- ✅ 逻辑完整性检查（SWOT四象限是否都有内容、BCG气泡数是否≥3）
- ✅ 最佳实践建议（"鱼骨图通常6M，你只填了3个，建议补充"）
- ✅ 拒绝生成条件（数据不足时报错，而不是硬凑）

---

### 4. 方法论正确性（Methodology Integrity）

**问题**：假装专家，没有真正理解这些模型的使用场景和分析逻辑。

**标准**：
- ✅ 符合学术/咨询行业标准（McKinsey SWOT、BCG Growth-Share Matrix原始定义）
- ✅ 使用场景明确（什么情况下用，什么情况下不该用）
- ✅ 常见误用警告（例如：BCG矩阵不适用于初创公司、鱼骨图不能替代5 Whys）
- ✅ 模型局限性说明（"此模型假设市场增长率可预测，不适用于颠覆性创新场景"）

## 📐 各模型的重构要求

### 🐟 Fishbone（鱼骨图）

#### 当前问题
- 鱼刺是直线div，不是标准的斜向箭头
- 6M标签没有解释（用户可能不知道"Man/Machine/Material"含义）
- 子原因是简单列表，缺少层级关系

#### 重构目标
```
视觉：
- SVG绘制标准鱼骨（主干线+斜刺+箭头）
- 鱼刺角度55°（符合石川馨原始设计）
- 鱼头用圆角矩形+问题描述
- 子原因用支线连接（不是悬浮文本）

数据验证：
- problem字段必填
- causes至少3个分类有内容（否则警告"分析不完整"）
- 每个分类下≥2个子原因（否则提示"需深挖"）

思维密度：
- 6M标签hover显示中英文解释
- 自动检测：哪些分类为空（提示"未分析XX维度"）
- 根因排序：支持标记P0/P1优先级

方法论：
- 使用场景：质量问题、项目延期、事故分析
- 不适用：战略规划、多目标优化
- 配合工具：5 Whys、Pareto图
```

### 📊 BCG矩阵

#### 当前问题
- 坐标轴刻度不清晰（没有0/10%/50%/100%标注）
- 气泡大小随意（没有映射真实营收规模）
- 缺少象限名称和战略建议
- 没有10%增长率分界线（BCG标准）

#### 重构目标
```
视觉：
- Canvas绘制精确坐标轴（带刻度和网格）
- 10%水平虚线（标注"增长率临界线"）
- 50%垂直虚线（标注"市场份额临界线"）
- 气泡面积正比于营收（带数值标签）
- 4象限背景色区分+emoji图标（⭐明星/🐄金牛/❓问题/🐕瘦狗）

数据验证：
- items至少3个（少于3个无法做组合分析）
- marketGrowth/marketShare范围0-100
- size>0（营收不能为负）
- 拒绝全部集中在一个象限（"数据异常，无分析价值"）

思维密度：
- hover显示战略建议：
  - 明星：持续投入，争取领导地位
  - 金牛：收割利润，少量维护投入
  - 问题：选择性投资，快速验证
  - 瘦狗：考虑退出或转型
- 自动标注风险业务（市场份额<10%且增长<5%）
- 显示业务组合健康度评分（金牛+明星占比）

方法论：
- 使用场景：成熟企业多业务组合分析
- 不适用：单一产品公司、初创公司（无"相对"市场份额）
- 数据来源：市场研究报告、财务报表
- 更新频率：每季度/半年度
```

### 📋 Kanban看板

#### 当前问题
- 列宽固定（不适配卡片数量）
- 卡片信息单薄（只有标题）
- 缺少WIP限制的视觉提示（超限应该变红）
- 没有泳道优先级排序

#### 重构目标
```
视觉：
- 列宽自适应（≤3张卡片紧凑，>5张卡片展开）
- 卡片丰富信息：
  - 标题+标签（P0/P1/P2配色）
  - 负责人头像（首字母圆形）
  - 截止日期（逾期变红）
  - 子任务进度条（3/5完成）
- WIP超限视觉警告（列头变红+感叹号）
- 拖拽排序动画（虽然演示不能真拖，但要有视觉暗示）

数据验证：
- columns至少2列（否则不是流程）
- wipLimit有值时，检查实际卡片数（超限警告）
- 卡片assignee建议≤2人（多人=责任模糊）
- Done列卡片数应该是最多的（否则提示"积压严重"）

思维密度：
- 显示流转效率：
  - 平均停留时间（模拟数据）
  - 瓶颈列高亮（卡片数最多的非Done列）
- 自动检测：长期停留卡片（标记🔥"需关注"）
- WIP健康度评分（In Progress / wipLimit * 100%）

方法论：
- 使用场景：敏捷开发、任务流程管理
- 不适用：非流程性工作（研究、战略规划）
- 最佳实践：
  - WIP限制=团队人数±1
  - Done列每周清理
  - 每日站会基于看板更新
```

### 🎯 Pyramid金字塔思维

#### 当前问题
- 连接线是直线SVG，视觉平淡
- 论据卡片无层级感（都是平铺）
- 缺少MECE原则的视觉提示
- 没有论证强度的可视化

#### 重构目标
```
视觉：
- 塔尖用3D渐变立体感（CSS perspective）
- 连接线用贝塞尔曲线（优雅流动感）
- 论据卡片错落排列（模拟金字塔层级）
- 支撑事实用缩进树状结构
- 论据强度条（根据facts数量显示1-3颗星）

数据验证：
- conclusion必填且简洁（≤30字）
- pillars数量3-5个（MECE原则：不多不少）
- 每个pillar下facts≥2条（否则论据不充分）
- 自动检测论据重复（文本相似度>70%警告）

思维密度：
- MECE检查提示：
  - 相互独立：论据间无交集（AI语义分析）
  - 完全穷尽：是否覆盖核心维度
- 论证链完整性：结论→论据→事实逻辑闭环
- 反例提示："当前论证假设XX，但未考虑YY场景"

方法论：
- 使用场景：战略分析、方案论证、咨询报告
- 不适用：数据探索（无明确结论时）、头脑风暴
- 黄金标准：
  - 结论具体可执行（不是"需要进一步研究"）
  - 论据MECE（相互独立、完全穷尽）
  - 事实可验证（有数据/案例支撑）
```

## 🚨 拒绝生成的条件

当数据不符合以下条件时，**拒绝生成并给出专业建议**：

### Fishbone
- ❌ problem为空 → "请明确要分析的核心问题"
- ❌ 只有1-2个分类有内容 → "鱼骨图需要多维度分析，建议至少从4个角度（人/机/料/法）分析"

### BCG
- ❌ items<3 → "BCG矩阵需要≥3个业务单元才有对比意义"
- ❌ 所有点在同一象限 → "业务过于集中，BCG分析无效，建议用其他工具"
- ❌ 初创公司数据 → "您的业务处于早期阶段，BCG矩阵不适用，建议用精益画布"

### Kanban
- ❌ 只有1列 → "看板需要≥2列表示流程"
- ❌ Done列为空 → "看板应该有已完成任务，当前数据不完整"

### Pyramid
- ❌ pillars<2 → "金字塔论证至少需要2个支撑论据"
- ❌ pillars>5 → "论据过多违反MECE原则，建议合并为3-5个核心论据"
- ❌ conclusion含糊（"可能"/"或许"/"待定"）→ "金字塔结论必须明确，请重新表述"
