# 叙事结构模板库

> 知识层 - 经过验证的汇报叙事框架，根据受众+场景自动匹配

---

## 框架选择决策树

```
用户场景输入
    │
    ├─ 受众是高管/董事会？
    │   └─ YES → 结论先行框架（Executive Summary First）
    │
    ├─ 受众是客户/投资人？
    │   └─ YES → 价值主张框架（Value Proposition）
    │
    ├─ 是季度/年度汇报？
    │   └─ YES → OKR进展框架（Progress Review）
    │
    ├─ 是新产品发布？
    │   └─ YES → 产品发布框架（Product Launch）
    │
    ├─ 是问题分析/决策？
    │   └─ YES → 问题-方案框架（Problem-Solution）
    │
    └─ 其他 → 通用框架（Generic）
```

## 1. 结论先行框架（Executive Summary First）

**适用场景**：向高管/董事会汇报，时间紧张（5-10分钟）

**核心逻辑**：先给结论，后补证据。高管要的是答案，不是推导过程。

### 页面结构（6页标准）
```javascript
P1: 封面
P2: 核心结论（1句话 + 3个关键数字）
P3: 战略对齐（为什么这么做？）
P4: 关键证据（数据/案例支撑）
P5: 下一步行动（时间线 + 资源需求）
P6: 备份页（Q&A预案）
```

### Block组合
- **P2必用**：hero + metric（结论 + 数字强化）
- **P3可选**：bullets（3条原因）或 swot（战略分析）
- **P4必用**：chart（趋势图）或 compare（对比）
- **P5必用**：timeline（路线图）+ bullets（资源需求）

### 示例：季度产品汇报
```javascript
slides: [
  { title: "封面", blocks: [{ type: "hero", title: "Q2 产品进展汇报" }] },
  
  { title: "核心结论", blocks: [
    { type: "hero", title: "已锁定核心场景作为突破口" },
    { type: "metric", items: [
      { value: "1", unit: "个", label: "闭环场景跑通", delta: "Q2目标" },
      { value: "80", unit: "%", label: "覆盖目标用户", delta: "" },
      { value: "3", unit: "个月", label: "开发周期", delta: "硬约束" }
    ]}
  ]},
  
  { title: "战略对齐", blocks: [
    { type: "swot", /* 战略选择依据 */ }
  ]},
  
  { title: "进展证据", blocks: [
    { type: "timeline", items: [/* 里程碑完成情况 */] }
  ]},
  
  { title: "下一步", blocks: [
    { type: "gantt", tasks: [/* Q3-Q4计划 */] }
  ]}
]
```

## 2. 价值主张框架（Value Proposition）

**适用场景**：向客户/投资人展示，需要建立信任

**核心逻辑**：痛点 → 解法 → 证明 → 下一步

### 页面结构（8页标准）
```javascript
P1: 封面
P2: 痛点洞察（客户真实问题）
P3: 解决方案（我们怎么做）
P4: 核心优势（为什么是我们）
P5: 成功案例（已验证的结果）
P6: 产品演示（可视化/Demo）
P7: 商业模式（如何合作）
P8: 下一步（行动号召）
```

### Block组合
- **P2必用**：bullets + stagger（逐条揭示痛点，制造共鸣）
- **P3必用**：split（左图右文，直观展示方案）
- **P4推荐**：grid（多列卡片，并列优势）
- **P5必用**：metric（数字说话）+ quote（客户证言）
- **P6可选**：media（视频演示）或 tabs（多场景切换）
- **P8必用**：hero（大字CTA） + bullets（后续步骤）

---

## 3. OKR进展框架（Progress Review）

**适用场景**：季度/年度复盘，强调目标达成

**核心逻辑**：目标 → 进展 → 分析 → 调整

### 页面结构（10页标准）
```javascript
P1: 封面
P2: 本期目标（O + KR）
P3: 完成情况（数字仪表盘）
P4: 亮点成果（做得好的）
P5: 问题分析（未达成的原因）
P6: 竞对动态（外部环境）
P7: 战略调整（下期优先级）
P8: 资源需求（人/钱/时间）
P9: 时间线（下期计划）
P10: Q&A
```

### Block组合
- **P2必用**：okr（目标树 + 进度条）
- **P3必用**：metric（关键数字） + chart（趋势）
- **P4推荐**：bullets + stagger（逐条揭示成果）
- **P5必用**：swot（内外部分析）或 compare（预期vs实际）
- **P7必用**：bullets（调整决策） + timeline（新路线图）
- **P9必用**：gantt（下期时间表）

## 4. 产品发布框架（Product Launch）

**适用场景**：新品发布会、路演、对外宣讲

**核心逻辑**：造势 → 揭晓 → 演示 → 行动

### 页面结构（12页标准）
```javascript
P1: 封面（悬念/预告）
P2: 行业痛点（为什么需要这个产品）
P3: 产品揭晓（名字 + Slogan）
P4: 核心特性（3-5个亮点）
P5-P8: 特性详解（每个特性1页，图文混排）
P9: 技术架构（可选，针对技术观众）
P10: 定价/购买（商业化信息）
P11: 上市时间（时间线）
P12: 收尾（大字CTA）
```

### Block组合
- **P1特殊**：hero（大字 + 悬念文案，无副标题）
- **P2必用**：bullets + stagger（痛点渐进揭示）
- **P3必用**：hero（产品名大字） + media（产品图/视频）
- **P4推荐**：grid（多列卡片，特性并列）
- **P5-P8推荐**：split（左图右文，每个特性1页）
- **P11必用**：timeline（上市路线图）
- **P12必用**：quote（金句收尾） + hero（CTA）

## 5. 问题-方案框架（Problem-Solution）

**适用场景**：提案/决策会议，需要推动行动

**核心逻辑**：问题 → 分析 → 方案 → 对比 → 决策

### 页面结构（8页标准）
```javascript
P1: 封面
P2: 问题定义（是什么问题？）
P3: 影响范围（不解决会怎样？）
P4: 根因分析（为什么发生？）
P5: 解决方案（怎么做？）
P6: 方案对比（为什么选这个？）
P7: 实施计划（时间 + 资源）
P8: 风险与应对
```

### Block组合
- **P2必用**：bullets + stagger（问题逐条呈现）
- **P3推荐**：metric（量化影响） + chart（趋势恶化）
- **P4推荐**：bullets（根因清单）或 swot（内外因分析）
- **P5必用**：split（方案图文）或 bullets（方案要点）
- **P6必用**：compare（方案A vs 方案B）
- **P7必用**：gantt（时间表） + bullets（资源清单）
- **P8推荐**：tabs（风险分类） + bullets（应对措施）

## 6. 通用框架（Generic）

**适用场景**：不确定受众或场景时的万能模板

### 页面结构（灵活8-12页）
```javascript
P1: 封面
P2: 背景/上下文
P3: 目标/主题
P4-P8: 核心内容（根据素材动态调整）
P9: 总结
P10: 下一步
```

### Block选择原则
- **有数据** → metric + chart
- **有时间顺序** → timeline 或 gantt
- **有对比/选择** → compare 或 tabs
- **有结构化内容** → bullets 或 grid
- **有战略分析** → swot 或 okr
- **有引用/观点** → quote

## 框架应用示例

### 场景1：季度产品汇报
```
用户输入："给产品团队汇报Q2进展，10分钟"
受众识别：团队（管理层性质）
框架匹配：OKR进展框架
理由：有明确时间周期（Q2）、需要展示完成情况
```

### 场景2：AI助手产品发布
```
用户输入："对外发布新AI助手，20分钟路演"
受众识别：公众/投资人
框架匹配：产品发布框架
理由：新产品+对外+需要造势
```

### 场景3：成本优化方案提案
```
用户输入："向CFO提案降低运营成本方案"
受众识别：高管（CFO）
框架匹配：结论先行框架（而非问题-方案）
理由：高管要结论不要过程，直接说"能省多少"
```

## 自适应调整规则

### 时长与页数匹配
- **5分钟** → 5-6页（1页/分钟）
- **10分钟** → 8-10页（考虑互动）
- **15分钟** → 10-12页
- **30分钟** → 15-18页（含备份页）

### 素材不足时的降级
- **缺数据** → metric改为bullets（文字描述）
- **缺图表** → chart改为bullets（关键结论）
- **缺案例** → 用【待填入】占位，生成后提醒用户
- **缺时间线** → timeline改为bullets（阶段清单）

### 素材过多时的聚合
- **10+个数据** → 只展示Top 3，其余放tabs或备份页
- **5+个方案** → 聚合为2-3类，用compare或tabs
- **长文本** → 提炼为3-5条bullets，原文放备注

## 常见错误

### ❌ 框架错配
```
错误：向高管汇报用"问题-方案"框架（8页推导过程）
正确：用"结论先行"框架（先说结论，高管追问再展开）
```

### ❌ 页数失控
```
错误：10分钟汇报做了20页
结果：讲不完 or 赶进度观众跟不上
正确：严格按"1分钟/页"预估，宁少勿多
```

### ❌ Block堆叠
```
错误：一页塞5个Block（hero + metric + bullets + chart + timeline）
正确：一页最多3个Block，其余内容拆页
```
