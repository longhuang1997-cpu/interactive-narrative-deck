# Narrative Engine · 叙事框架自动匹配

> 知识层 - 根据内容特征自动推荐叙事结构，不需要用户懂叙事设计

## 核心机制

Claude收到用户需求后，先判断内容属于哪个叙事类型，再套对应框架生成slides结构。

---

## 四种叙事框架

### 框架A：问题-方案型（最常用）
**触发特征**：用户提到"遇到问题"、"效率低"、"流失"、"瓶颈"、"改进"
**结构**：
```
封面 → 现状数据 → 问题拆解(渐进) → 原因分析 → 解决方案对比 → 推荐方案 → 行动路线图 → 收尾
```
**适合场景**：管理层汇报、改善提案、复盘总结

---

### 框架B：数据-洞察型
**触发特征**：用户提到"数据"、"报告"、"趋势"、"同比"、"指标"、"KPI"
**结构**：
```
封面 → 核心指标(metric) → 趋势图(chart) → 结构拆解 → 关键洞察(bullets) → 下步行动 → 收尾
```
**适合场景**：季报、年报、数据复盘

---

### 框架C：产品-发布型
**触发特征**：用户提到"新产品"、"发布"、"上线"、"功能"、"路演"、"投资人"
**结构**：
```
封面 → 痛点(问题共鸣) → 解法亮点 → 功能对比(compare) → 数据证明(metric) → 使用场景 → 上线计划(timeline) → 收尾
```
**适合场景**：产品发布会、路演、招商

---

### 框架D：故事-共鸣型
**触发特征**：用户提到"培训"、"分享"、"经验"、"我们是怎么做的"、"案例"
**结构**：
```
封面 → 背景故事(hero+bullets) → 挑战时刻 → 转折点 → 解法过程(timeline) → 结果数据(metric) → 给大家的启示 → 收尾
```
**适合场景**：技术分享、内部培训、经验传递

---

## Claude执行规则

收到用户需求时，按以下步骤：

1. **识别框架**：从用户描述中匹配触发特征，选A/B/C/D之一
2. **告知用户**：说明选了哪个框架、为什么，询问是否调整
3. **补充缺口**：框架里需要数据的地方，如用户未提供，标注`【待填入】`而非编造
4. **生成结构**：按框架顺序生成slides数组

**示例**：
> 用户："帮我做Q3数据汇报，营收128万，续约率92%，有3个问题要说"
> Claude判断：触发"数据"+"问题"→ 框架B为主+框架A的问题拆解部分 → 混合结构
> 告知："我用数据-洞察型框架，在趋势图后加问题分析，8页结构如下..."
